# AI大白话知识库 Schema v2 设计文档

## 一、目标

Schema v2 是 AI大白话知识库的统一数据标准。

目标：

-   支持知识库直接回答
-   支持 AI 生成解释
-   支持搜索匹配
-   支持知识关联推荐
-   支持后台审核
-   支持长期扩展

一个词条不仅是一个解释，而是一个知识节点。

------------------------------------------------------------------------

# 二、标准字段结构

``` json
{
  "term": "",
  "aliases": [],

  "category": "",
  "subcategory": "",
  "ecosystem": "",

  "knowledgeLevel": "",
  "targetAudience": [],

  "summary": "",
  "memoryPoint": "",
  "analogy": "",
  "examples": [],

  "commonQuestion": [],
  "avoidMisunderstanding": "",

  "relatedTerms": [],

  "searchIntent": [],
  "priority": "",

  "status": "",
  "version": "",

  "createdAt": "",
  "updatedAt": ""
}
```

------------------------------------------------------------------------

# 三、字段说明

## 基础识别字段

### term

正式名称。

例如：

``` json
"term": "Token"
```

规则：

-   优先使用行业通用名称
-   英文技术词保留英文
-   中文已有统一叫法时使用中文

------------------------------------------------------------------------

### aliases

用户可能搜索的别名。

例如：

``` json
[
 "AI Token",
 "token数量",
 "模型token"
]
```

作用：

提高搜索命中率。

------------------------------------------------------------------------

# 四、分类体系字段

## category

一级分类。

例如：

``` json
"category": "大模型与LLM"
```

------------------------------------------------------------------------

## subcategory

二级分类。

例如：

``` json
"subcategory": "模型工作原理"
```

------------------------------------------------------------------------

## ecosystem

所属生态。

例如：

``` json
"ecosystem": "AI基础设施"
```

用于知识关联。

例如：

Token:

关联：

-   Prompt
-   Context Window
-   LLM

------------------------------------------------------------------------

# 五、用户画像字段

## knowledgeLevel

知识难度。

枚举：

``` text
beginner
intermediate
advanced
```

------------------------------------------------------------------------

## targetAudience

目标用户。

支持多选：

``` json
[
 "normal",
 "creator",
 "developer",
 "business"
]
```

------------------------------------------------------------------------

# 六、解释内容字段

## summary

一句话解释。

要求：

-   50字以内
-   小白能理解
-   不堆技术词

示例：

Token：

> AI理解文字时拆分出来的小单位。

------------------------------------------------------------------------

## memoryPoint

记忆点。

要求：

一句用户能记住的话。

示例：

> Token就像AI阅读文字时使用的小积木。

------------------------------------------------------------------------

## analogy

生活类比。

要求：

必须具体。

禁止：

空泛比喻。

------------------------------------------------------------------------

## examples

真实场景。

至少2个。

格式：

``` json
[
 "场景1",
 "场景2"
]
```

------------------------------------------------------------------------

# 七、用户搜索意图字段

## commonQuestion

用户可能提出的问题。

例如：

Token:

``` json
[
 "Token是什么",
 "为什么AI收费和Token有关",
 "Token越多越好吗"
]
```

------------------------------------------------------------------------

## searchIntent

搜索目的。

例如：

``` json
[
 "不知道是什么",
 "想理解计费方式",
 "想解决使用问题"
]
```

------------------------------------------------------------------------

# 八、风险控制字段

## avoidMisunderstanding

常见误解。

例如：

Token：

> AI里的Token不是登录验证用的Token。

作用：

避免模型解释错误。

------------------------------------------------------------------------

# 九、关联体系

## relatedTerms

相关知识节点。

例如：

``` json
[
 "Context Window",
 "Prompt",
 "Embedding"
]
```

要求：

不要随机推荐。

必须存在知识关系。

------------------------------------------------------------------------

# 十、运营字段

## priority

优先级：

``` text
P0
P1
P2
```

说明：

P0：

高频搜索，首批上线。

P1：

重要扩展。

P2：

长期维护。

------------------------------------------------------------------------

## status

状态：

``` text
draft
review
approved
deprecated
```

------------------------------------------------------------------------

## version

知识版本。

例如：

``` text
1.0.0
```

------------------------------------------------------------------------

# 十一、质量标准

每个词条上线前评分：

## 准确性

5分：

技术正确，无误导。

------------------------------------------------------------------------

## 易懂程度

5分：

普通用户可以理解。

------------------------------------------------------------------------

## 类比质量

5分：

帮助建立记忆。

------------------------------------------------------------------------

## 实用价值

5分：

用户知道为什么需要。

------------------------------------------------------------------------

## 关联价值

5分：

能引导用户继续探索。

------------------------------------------------------------------------

上线标准：

平均分 \>= 4。

# 十三、设计原则

1.  知识库不是百科，而是解释系统。

2.  优先解决用户问题，而不是展示技术。

3.  英文技术词保留原名，中文解释辅助。

4.  每个词条必须连接知识网络。

5.  内容必须适合AI时代持续扩展。
